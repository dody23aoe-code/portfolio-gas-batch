# 再開できる発注書生成サンプル

架空の注文600行から、仕入れ先ごとに発注書シートを作る Google Apps Script のサンプルです。注文は30仕入れ先・各20行で、標準では30帳票になります。出力は同じスプレッドシート内のシートです。PDF作成、メール送信、実際の発注は行いません。

実行位置を Script Properties に保存し、1分間隔の時間トリガーで続きから処理します。1回あたり最大5帳票、または実行開始から240秒で新しい帳票への着手を止めます。少量のデータでも分割実行を観察できます。

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `src/Core.js` | 入力検証、仕入れ先別の並べ替え・ページ分割、再開ループ |
| `src/Main.js` | 雛形生成、シート入出力、進捗保存、ロック、トリガー |
| `src/appsscript.json` | V8・タイムゾーン・必要な権限 |
| `data/orders.csv` | UTF-8 BOM付きCSV、ヘッダー＋架空の注文600行 |
| `tests/batch.test.js` | Node.js標準機能によるテストとGASサービスのメモリ実装 |
| `tools/generate-sample.js` | CSVの再生成 |
| `.clasp.example.json` | claspの接続設定例 |

外部ライブラリはありません。`package.json` は Node.js のモジュール形式をこのプロジェクト内で固定するための設定です。パッケージのインストールは不要で、npm / pnpm は使用しません。

## 導入

### clasp でアップロードする場合

既に利用できる clasp 3系と Google アカウントが必要です。このサンプルには clasp のインストール処理を含めていません。clasp がない場合は次の「ブラウザだけで導入」を使えます。

1. 新しい空の Google スプレッドシートを作り、「拡張機能 → Apps Script」を開きます。スプレッドシートに紐づく専用プロジェクトを使用します。
2. Apps Script の「プロジェクトの設定」でスクリプトIDを確認します。
3. リポジトリのルートで `.clasp.example.json` を `.clasp.json` にコピーし、`scriptId` を置き換えます。`rootDir` は `src` のままにします。
4. [Apps Script のユーザー設定](https://script.google.com/home/usersettings)で Apps Script API を有効にします。
5. 以下を実行します。認証済みならログインは不要です。

```text
clasp login
clasp show-file-status
clasp push
```

`show-file-status` でアップロード対象が `Core.js`、`Main.js`、`appsscript.json` の3ファイルであることを確認してください。新規の専用プロジェクトへのアップロードを前提としています。設定とコマンドの詳細は [clasp の公式リポジトリ](https://github.com/google/clasp)にあります。

`.clasp.json` と認証設定は `.gitignore` で除外しています。認証コマンドは通常、ツール自身のユーザー設定領域を使用します。

### ブラウザだけで導入する場合

1. 新しいスプレッドシートから「拡張機能 → Apps Script」を開きます。
2. `Core`、`Main` のスクリプトファイルを作り、それぞれ `src/Core.js`、`src/Main.js` の全文を貼り付けます。既存の空の `Code.gs` は削除して構いません。
3. 「プロジェクトの設定」でマニフェストファイルの表示を有効にし、`appsscript.json` を同梱の内容で置き換えて保存します。

### 最初の実行

1. エディタで `setupDemo` を実行し、スプレッドシートの操作とトリガー管理の権限を許可します。
2. `注文`、`発注書雛形`、`処理記録` の3シートができます。注文データはCSVと同じ600行です。`setupDemo` は既存シートや処理状態がある場合は上書きせずエラーにします。
3. 必要なら開始前に雛形の色・フォント・列幅を変更します。書き込み領域は `B3:B6`、`F7`、`A9:F108` です。この範囲を移動・結合しないでください。明細見出しは8行目です。
4. `startBatch` を実行します。以後は時間トリガーが自動で `resumeBatch` を呼び出します。ブラウザを閉じても続行します。
5. スプレッドシートを再読み込みすると「発注書サンプル」メニューからも操作できます。

CSV自体を試す場合は、`setupDemo` 後、開始する前に `注文` シートだけをCSVで置き換えます。ファイルのインポートで「現在のシートを置換」を選び、カンマ区切り・数値変換を有効にしてください。シート名は `注文`、列順はCSVのままにします。

## 実環境での確認

1. `startBatch` の最初の実行後、通常は `処理記録` の2行目が `RUNNING`、完了帳票数5、処理済行数100になります。処理が遅い場合は5帳票より少ない時点で区切ります。
2. Apps Script の「トリガー」に `resumeBatch` が1件あることを確認します。時間トリガーは厳密な時刻を保証しないため、数分待って進捗を確認します。
3. 完了時は `COMPLETED`、完了帳票数30/30、処理済行数600/600、`PO_` で始まる出力シート30枚、記録の明細30件になります。各帳票の金額は数量×単価、合計は明細金額の合計です。税計算はありません。
4. 完了時にはこのサンプルの `resumeBatch` トリガーが削除されます。他のハンドラのトリガーは削除しません。
5. 完了後に `startBatch` や `resumeBatch` を再実行しても帳票数が増えないことを確認します。
6. 中断・再開を試すには、新しいスプレッドシートと専用スクリプトで開始し、最初の実行後にトリガーを手動削除します。進捗が止まることを確認後、`startBatch` を実行すると保存位置から続行し、トリガーも復旧します。

実行中にエディタの停止ボタンで中断した場合も、巡回トリガーが残っていれば再開します。処理記録は最後に保存した地点を示すため、実行中の帳票が先に見える場合があります。利用可能な完了結果は `COMPLETED` を確認してください。

## 入力と再開の仕組み

- 列は `order_id,supplier_id,supplier_name,item_name,quantity,unit_price` です。注文IDは一意で、注文・仕入れ先IDは英大文字・数字・ハイフンだけを使用します。同じ仕入れ先IDには同じ名称が必要です。
- 数量は正の整数、単価は0以上の整数（円）です。数値文字列、小数、金額の安全な整数範囲超過は拒否します。仕入れ先名と商品名は必須文字列で、数式として扱われる可能性がある記号 `= + @ -` から始まる名称も拒否します。完全な空行は無視します。
- 開始時に入力を検証し、注文の値と雛形を非表示シートへ保存します。`RUNNING` になった後の入力・雛形の編集は今回の出力に反映しません。`PREPARING` で失敗した場合は入力を修正して再開できます。
- 仕入れ先ID、注文IDの順に並べ、1帳票は同一仕入れ先の最大100行とします。100行を超える仕入れ先は複数ページになります。ページサイズを変える場合は雛形と書き込み範囲も変更が必要です。
- 出力名はジョブIDと帳票の通し番号で固定します。名前を指定して雛形から作成し、既にあればそのシートに同じ内容を書き直します。出力の作成直後に停止しても、別のシートを作りません。
- `出力を書き込み・flush → 記録の固定行へ書き込み・flush → 次の帳票位置を保存` の順に進めます。複数サービスをまたぐトランザクションではないため、同じ書き込みが再実行されることはありますが、出力・記録ともに重複を残さない設計です。
- Script Lock で同時実行を防ぎます。再開トリガーは処理前に用意するため、時間切れで例外処理が動かなかった場合にも次の呼び出しが残ります。毎回スナップショットから作業一覧を再構築し、JavaScriptのメモリには依存しません。
- 処理記録の2行目は最新状況、5行目以降は帳票ごとの実績です。実行試行を追記する履歴ではありません。再実行時に同じ実績行を更新するため、更新日時は変わることがあります。

## エラー時と適用範囲

通常のエラーは処理記録に「再試行待ち」と理由を残し、保存位置を保ったまま次回トリガーで再試行します。Apps Script の「実行数」でも例外を確認できます。恒久的なエラーではトリガーを手動削除して原因を修正し、`startBatch` で再開してください。記録シートへのアクセス自体が失敗した場合、記録は更新できません。

このサンプルは1スクリプト・1スプレッドシート・1ジョブです。実行担当の Google アカウントを1つに統一してください。別アカウントのインストール型トリガーは同じ方法では管理できません。新しい発注を始める場合は、新しいスプレッドシートと専用スクリプトを使用します。完了済み状態を消して同じジョブを再発行する機能は設けていません。

実行中は非表示のスナップショット、出力シート、処理記録、Script Properties、設定値を変更・削除しないでください。非表示は編集権限の保護ではありません。入力には数式ではなく値を使用してください。初期化が中断して `PREPARING` の間は、次回の準備時に注文を読み直します。

Apps Script の通常の実行上限は1回6分です。本サンプルは240秒を超えた時点で新規帳票への着手を停止します。進行中のAPI呼び出しを中断する機能ではないため、1帳票を100行に制限しています。時間トリガーの1日あたりの総実行時間など、その他の上限は回避しません。日次上限に達した場合は利用枠の回復後に再開してください。[Google公式の制限一覧](https://developers.google.com/apps-script/guides/services/quotas)

注文一覧の読み込み・検証・初期スナップショット作成は1回の実行内で行います。この準備自体が6分を超える規模、スプレッドシートのセル上限を超える規模、アクセス権の失効や恒久的な障害まで無条件に完了を保証するものではありません。時間トリガーは実行者の権限で動作します。[Google公式の時間トリガー説明](https://developers.google.com/apps-script/guides/triggers/installable)

## ローカルでの確認

Node.js 20以上を用意し、リポジトリのルートで実行します。Googleの認証やネットワーク接続、パッケージのインストールは不要です。

```text
node --test tests/batch.test.js
```

テスト内容:

- CSVと生成データの一致、600行・30仕入れ先の確認。
- 一括処理と5帳票ずつの再開で、全出力セルが同じになること。
- 全600注文が各1回だけ出力され、完了後の再実行で増えないこと。
- シート作成後、ヘッダー・明細・記録保存後、位置保存の前後、進捗更新後、トリガー削除時の障害から復旧すること。
- スクリプトを読み直してから再開し、メモリ上の進捗がなくても動くこと。
- 入力変更の隔離、ロック競合、空入力、不正入力、初期化エラーの修正後の再開。
- 同一仕入れ先100行超のページ分割と順序の安定性。
- 1帳票70秒、総計35分相当の仮想時計で時間予算による中断・再開を確認。

GASサービスの入出力はメモリ上で再現しています。Google側の実際の実行時間、トリガー発火、認証、帳票の見た目はローカルテストでは検証できません。「実環境での確認」の手順を併用してください。

CSVを同じ内容で再生成する場合:

```text
node tools/generate-sample.js
```

## 公開用ファイル

データの会社名・商品名はすべて架空です。接続設定、認証情報、ローカル作業報告 `REPORT.md` は `.gitignore` で除外しています。GitHubリポジトリの作成やpushを行う処理は含まれていません。
